# Lab: Multi-Region VM Logging into Sentinel with Initial Access Detection

**Date:** 2026-07-30

## Objective

Build the basic detection pipeline end-to-end: VMs → Log Analytics → Sentinel analytics rule → incident, and observe it working across regions.

## What Was Done

- Deployed two VMs in different Azure regions.
- Created a Log Analytics workspace.
- Enabled [[Microsoft Sentinel]] on the workspace and configured data connectors.
- Connected both VMs to the workspace via the Azure Monitor Agent (AMA).
- Created analytics rules targeting the **Initial Access** MITRE ATT&CK tactic.
- Managed everything from the Microsoft Defender portal, since Sentinel now runs there rather than the Azure portal.
- Reviewed the incidents generated by the rules.

## Observations

- Sentinel administration is now done through the Defender portal — this isn't just a UI change, it's the unified security operations platform Microsoft has been migrating customers to. The Azure portal path for Sentinel is being retired (fully gone March 2027).
- Incidents were successfully generated from the Initial Access rule, confirming the full chain worked: AMA → Log Analytics ingestion → connector → analytics rule → incident.
- Using two regions didn't change the detection pipeline itself — the workspace and rules are region-agnostic once logs are flowing in, which is the point (centralized logging regardless of where the workload sits).

## Why It Matters for SC-100

- This is the practical version of the exam objective "design a solution for detection and response that includes XDR and SIEM" and "design a SOAR solution using Microsoft Sentinel and Microsoft Defender XDR" — connectors → analytics rules → incidents is exactly that pipeline.
- Directly exercises "evaluate threat detection coverage by using MITRE ATT&CK matrices" — the Initial Access rule is one cell in that coverage map, not an isolated detection.
- AMA is the same collection mechanism used for hybrid/multicloud monitoring (via Azure Arc) — this lab's VM-to-workspace path is the foundation that scales to non-Azure sources.
- The Sentinel-to-Defender-portal move is worth remembering specifically because exam prep material may still describe the old Azure-portal experience — the architecturally current answer is the unified Defender portal.
