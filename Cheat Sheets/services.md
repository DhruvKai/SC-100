# Services

One-line description per service. Update whenever a new service note is created.

| Service                                                    | Description                                                                                                                                                                                                                                                     |
| ---------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [[Zero Trust]]                                             | Strategic principle — verify explicitly, least privilege, assume breach — used to evaluate every security control.                                                                                                                                              |
| [[Conditional Access]]                                     | Entra ID policy engine that grants, blocks, or limits sign-in access based on identity, device, and risk signals.                                                                                                                                               |
| [[Cloud Adoption Framework (CAF)]]                         | Microsoft's seven-methodology roadmap for adopting and operating Azure; sequences when/how security and governance are embedded; Manage methodology's Unified Operations model answers hybrid/multicloud monitoring design.                                    |
| [[Microsoft Sentinel]]                                     | Cloud-native SIEM + SOAR — ingests logs, correlates incidents, automates response.                                                                                                                                                                              |
| [[Microsoft Defender]]                                     | Umbrella family of threat protection products, unified under Defender XDR.                                                                                                                                                                                      |
| [[Azure Security Logging]]                                 | Six core log sources (Activity Log, Resource Logs, VM guest logs, Storage Analytics, network flow logs, Entra ID reports) that feed centralized logging design.                                                                                                 |
| [[Logic Apps]]                                             | Serverless workflow/automation engine — the mechanism behind Sentinel SOAR playbooks.                                                                                                                                                                           |
| [[Security Posture Assessments]]                           | Continuous MCSB-benchmarked scoring of resource configuration across hybrid/multicloud, via Defender for Cloud Secure Score.                                                                                                                                    |
| [[Security Scoring Dashboards]]                            | Map of which Microsoft score (Secure Score, Advisor, Compliance Manager, Regulatory Compliance) answers which question.                                                                                                                                         |
| [[Cloud Adoption Security Review (CASR)]]                  | Checklist-driven review scoring a baseline-secured landing zone against the CAF Secure methodology; self-assessed or Microsoft-led.                                                                                                                             |
| [[Azure Landing Zones]]                                    | Multi-subscription platform + application environment (management groups, subscription vending, network topology) established in CAF's Ready phase.                                                                                                             |
| [[Azure Well-Architected Framework (WAF)]]                 | Five pillars + self-assessment for evaluating a single workload's architecture; Security pillar is WAF's SC-100-relevant piece.                                                                                                                                 |
| [[Microsoft Cybersecurity Reference Architectures (MCRA)]] | Microsoft's downloadable capability-to-Zero-Trust reference architecture deck; target-state and gap-analysis tool.                                                                                                                                              |
| [[Microsoft Cloud Security Benchmark (MCSB)]]              | Prescriptive, cross-cloud control framework (Domain → Control → Subcontrol) pre-mapped to CIS/NIST/PCI-DSS; scored via Secure Score.                                                                                                                            |
| [[Ransomware Resiliency and BCDR]]                         | Microsoft's three-phase strategy (Prepare/Limit/Prevent) treating recover-without-paying as the primary goal; backups as an attacker target.                                                                                                                    |
| [[Compliance and Privacy]]                                 | Translating regulation into controls via Purview's six compliance solutions vs. Priva's privacy-specific tools (Privacy Risk Management, Subject Rights Requests).                                                                                              |
| [[Priva]]                                                  | Privacy management product — Subject Rights Requests (DSAR/erasure fulfillment) and Privacy Risk Management (overexposure/transfer/minimization detection), scoped to the Microsoft 365 data estate.                                                          |
| [[AI and Copilot Security Architecture]]                   | AI's dual architectural role — securing AI as a workload (Purview DSPM, Defender for Cloud AI-SPM, Content Safety/Prompt Shields, Entra Agent ID) vs. using AI as a security capability (Microsoft Security Copilot).                                          |
| [[Microsoft Security Copilot]]                              | Generative-AI SOC assistant embedded in Defender XDR/Sentinel/Entra/Intune/Purview + standalone portal; SCU-billed capacity, promptbooks, and configurable-autonomy agents (Phishing Triage, CA Optimization, Purview DSPM, Vuln Remediation, TI Briefing).      |
| [[Data Security Posture Management (DSPM)]]                | Two similarly-named products: Purview DSPM (data estate — M365/Azure/Fabric/SaaS) vs. Defender for Cloud data-aware security posture (cloud data stores, feeds attack paths).                                                                                   |
| [[Security Operations]]                                    | SOC architecture — combining SIEM (Sentinel), XDR (Defender), and SOAR (playbooks) via the unified platform, Sentinel workspace topology (single vs. Direct-link/Co-Management/N-Tier + Primary workspace), MITRE ATT&CK coverage across Enterprise/Mobile/ICS. |
| [[Threat Intelligence]]                                    | Sourcing/operationalizing CTI via STIX objects — Defender TI connector vs. TAXII vs. upload API — and Threat Intelligence (raw indicators) vs. Threat Analytics (curated campaign reports). MDTI converged into Defender XDR/Sentinel Aug 2026.                 |
| [[Identity as the Security Perimeter]]                     | Network perimeter → identity perimeter shift, made concrete via Global Secure Access — Entra Private Access (ZTNA/VPN replacement) vs. Internet Access (SWG) vs. Internet Access for Microsoft services (Compliant Network, Tenant Restrictions).               |
| [[Identity and Access Management (IAM)]]                   | Authorization architecture — Azure RBAC vs. Entra ID roles, managed identity vs. service principal, tenancy and directory objects (app registration vs. enterprise application), AD DS hardening.                                                              |
| [[Securing Privileged Access]]                              | Enterprise Access Model (Control/Management/Data-Workload planes) containing standing privilege — PIM (JIT activation) vs. entitlement management (bundled access) vs. CIEM (right-sizing over-provisioned permissions) vs. privileged access workstations.    |
| [[Cloud Workload Protection (CWPP)]]                        | Runtime protection plans in Defender for Cloud (Servers, Containers, SQL, Storage, APIs) — agentless scanning (periodic baseline) vs. agent-based EDR (real-time, Defender for Servers Plan 2).                                                                |
| [[CSPM and CWPP]]                                           | How posture (prevent), workload protection (detect/respond), and EASM (outside-in discovery) combine into Defender for Cloud's CNAPP — attack path analysis correlating CSPM + CWPP + DSPM + CIEM + EASM signals into one prioritized risk view.               |
| [[Securing Server and Client Endpoints]]                    | Endpoint type → mechanism mapping — Defender for Servers (CWPP) vs. Intune MDM/MAM (client/BYOD) vs. Windows LAPS (local admin passwords) vs. Defender for IoT Enterprise vs. OT editions.                                                                      |
| [[Securing IaaS and PaaS Services]]                         | Deployment model → network control mapping — NSG/Azure Firewall/Bastion/JIT for IaaS vs. Private Link/Service Endpoint/managed identity for PaaS, enforced portfolio-wide via MCSB/Azure Policy.                                                                |
| [[Azure Arc]]                                                | Projects non-Azure servers/Kubernetes/SQL Server into Azure Resource Manager (outbound-only agent) — the prerequisite that extends Azure Policy, RBAC, Defender for Cloud, and Sentinel to hybrid/multicloud resources.                                        |
| [[Network Security Architecture]]                            | Layered perimeter/topology design — WAF vs. Azure Firewall, DDoS Basic vs. Standard, Firewall Manager for centralized policy, and when a third-party NVA is actually justified over Azure Firewall Premium.                                                    |
| [[Private Link]]                                              | Private Endpoint (consumer) vs. Private Link Service (provider) mechanics — private DNS zone resolution, cross-tenant manual approval, per-resource-instance private IP.                                                                                       |
| [[Threat Modeling]]                                           | Design-time STRIDE analysis over a data flow diagram, per business-critical app — Microsoft Threat Modeling Tool; layered with OWASP Top 10 for LLM Applications for AI/agent systems; contrasted with runtime attack path analysis.                          |
| [[DevOps Security]]                                            | Microsoft Defender for DevOps — secret scanning, SAST (CodeQL), SCA, and IaC scanning across GitHub/Azure DevOps, surfaced via PR annotations and centralized into Defender for Cloud's Secure Score.                                                          |
| [[Data Classification and Protection]]                        | Discovery (SITs/EDM/classifiers) → classification (sensitivity labels) → handling (DLP/retention/Rights Management) → encryption (CMK vs. MMK, Always Encrypted) pipeline — the mechanism [[Data Security Posture Management (DSPM)\|DSPM]] scores.            |
| [[Purview]]                                                    | Orientation map across Purview's three areas — Data Map/Unified Catalog/lineage (governance), Security (DLP/labels), Risk & Compliance (audit/eDiscovery) — Collections RBAC vs. Azure RBAC.                                                                    |
| [[Microsoft Defender XDR]]                                     | AIR (entity-level auto-remediation) vs. Attack Disruption (real-time autonomous containment) vs. Advanced Hunting (native schema) vs. Unified RBAC — the XDR-specific capabilities layered under Sentinel/SOAR in Security Operations.                        |
| [[Key Vault]]                                                  | Standard/Premium/Managed HSM tiers (plus Azure Dedicated HSM and Payment HSM), Azure RBAC vs. legacy access policies, soft-delete vs. purge protection — the vault mechanism underneath the CMK decision in Data Classification and Protection.                |
| [[SaaS Application Discovery and Control]]                    | Defender for Cloud Apps (CASB) — Cloud Discovery (Shadow IT) vs. OAuth App Governance vs. Conditional Access App Control (connector vs. reverse-proxy) vs. access vs. session policies.                                                                        |
| [[Entra ID]]                                                   | License tiers — Free (Security Defaults) vs. P1 (Conditional Access) vs. P2 (Identity Protection, PIM) vs. Entra ID Governance add-on (Entitlement Management, Access Reviews).                                                                                |
| [[PIM]]                                                        | Eligible vs. active role assignment, activation requirements (MFA/approval/justification/duration), and PIM for Groups extending JIT beyond directory roles.                                                                                                    |
| [[Intune]]                                                     | Microsoft Endpoint Manager (retired brand) → Intune; co-management workload sliding, Windows Autopilot/ESP, and Endpoint Privilege Management (JIT local admin elevation, Intune Suite add-on).                                                                 |
| [[Network Security Group]]                                     | Rule mechanics — priority, default rules, service tags vs. Application Security Groups, subnet vs. NIC association (cumulative evaluation).                                                                                                                    |
| [[Azure Firewall]]                                             | Rule mechanics — NAT (DNAT) vs. network vs. application rules, processing order, SNAT, Firewall Policy, threat intelligence-based filtering.                                                                                                                    |
| [[Front Door and Application Gateway]]                         | Global edge (Anycast, CDN, failover) vs. regional VNet-based L7 reverse proxy — both attach the same WAF engine; Front Door Premium adds Private Link origin.                                                                                                   |
| [[DDoS Protection]]                                            | Basic (automatic) vs. Standard family — DDoS Network Protection (VNet-wide, cost protection, Rapid Response) vs. DDoS IP Protection (per-IP, pay-as-you-go).                                                                                                    |
| [[Azure Policy]]                                                | Azure Policy drives Secure Score — MCSB initiative (auto-assigned) → policy compliance → recommendations; Deny vs. Audit effects, remediation tasks, custom initiatives.                                                                                       |
| [[Trusted Platform Module (TPM)]]                               | Hardware root of trust — Secure Boot vs. Trusted Boot vs. Measured Boot, Device Health Attestation feeding the Conditional Access compliant-device signal, TPM-backed BitLocker/Windows Hello for Business/Credential Guard.                                   |
| [[API Management and Security]]                                 | Azure API Management as the API-layer policy enforcement point — OAuth2/JWT validation vs. subscription keys, throttling/quotas/versioning, vs. WAF's HTTP-payload protection; classic (Consumption/Developer/Basic/Standard/Premium) vs. v2 (Basic v2/Standard v2/Premium v2) tiers, VNet integration only from Premium (classic) or any v2 tier up.                                                                                 |
| [[Container and Kubernetes Security]]                           | AKS security across build/cluster/network/runtime — Azure RBAC for Kubernetes Authorization vs. native Kubernetes RBAC, Microsoft Entra Workload ID vs. retired AAD Pod Identity, Defender for Containers (detect) vs. Azure Policy for Kubernetes (prevent). |
| [[Identity Protection]]                                          | Entra ID's risk-detection engine — user risk vs. sign-in risk, risk levels, and how risk-based Conditional Access policies consume the score to challenge/block/require password reset.                                                                     |
| [[Azure Bastion]]                                                | Browser/native-client RDP-SSH with no public IP on the target VM — Basic/Standard/Premium/Developer SKUs, contrasted with JIT VM access.                                                                                                                    |
| [[Network Watcher and Lighthouse]]                               | Two unrelated services on one page — Network Watcher's diagnostic tools (IP flow verify, connection monitor, packet capture) and Azure Lighthouse's cross-tenant delegated administration.                                                                  |
| [[Securing Microsoft 365]]                                       | Ties the M365 domain together — Defender for Office 365 (Plan 1 vs. Plan 2) vs. Defender for Cloud Apps, Secure Score for productivity/collaboration, routed into the unified Defender XDR queue.                                                          |
| [[Security Adoption Framework (SAF)]]                             | Microsoft's umbrella, role-aware security modernization model — business scenarios → security disciplines → technology pillars — integrating MCRA, SDL, Zero Trust/CISO workshops, and IR playbooks into one structure.                                    |
| [[Secure Future Initiative (SFI)]]                                | Microsoft's internal, multi-year engineering commitment (launched Nov 2023) — six pillars mapped to Zero Trust and NIST CSF; one of the sources MCSB synthesizes.                                                                                            |
